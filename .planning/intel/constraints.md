## SPEC: gemba-lite — Native dispatch workspace

- **source:** `docs/design/gemba-lite.md`
- **precedence:** 0 (highest among SPECs in this set)
- **type:** api-contract + nfr + schema

### Constraint G-1 — OrchestrationPlaneAdaptor interface additions (api-contract)

Add three methods to `core.OrchestrationPlaneAdaptor`:

```go
type SessionInputMode string
const (
    InputLiteral SessionInputMode = "literal"
    InputKeys    SessionInputMode = "keys"
    InputSignal  SessionInputMode = "signal"
)

type SessionInput struct { Keys string; Mode SessionInputMode }

type SessionEvent struct {
    Kind  string             // output | status | exit | disconnect
    Bytes []byte
    Meta  map[string]any
}

type OrchestrationPlaneAdaptor interface {
    // ...existing...
    SendInput(ctx context.Context, sessionID string, in SessionInput) error
    ResizeSession(ctx context.Context, sessionID string, cols, rows int) error
    StreamSession(ctx context.Context, sessionID string) (<-chan SessionEvent, error)
}
```

Adapters that cannot satisfy a method return `core.KindUnsupported`; SPA renders read-only fallback.

### Constraint G-2 — Backend `Streamable` extension (api-contract)

`internal/adapter/native/backend.Backend` retains existing surface; add one optional interface:

```go
type Streamable interface {
    StreamPane(ctx context.Context, sessionID string) (<-chan []byte, error)
}
```

Non-tmux backends served by HTTP-layer polling fallback (`capture-pane` every 500ms, diff vs last snapshot).

### Constraint G-3 — HTTP endpoints (api-contract)

1. `GET /api/sessions/{id}/stream` — SSE. Events: `snapshot` (initial `capture-pane -p -e -J -S -2000`), `output` (incremental from `pipe-pane`), `status` (working/prompting/idle).
2. `POST /api/sessions/{id}/input` — body `{ keys: string, mode: "literal" | "keys" }`. Literal → `tmux send-keys -t <pane> -l -- <keys>`. Keys → `tmux send-keys -t <pane> -- <keys>`. Requires confirm-nonce middleware; every call emits audit event.
3. `GET /api/sessions/{id}/status` — JSON: `worktree {path,branch,ahead,behind}`, `git` (porcelain entries), `beads` (assignments touched), `assignment {bead_id,title}` or null.

### Constraint G-4 — Adapter implementation matrix (nfr / portability)

| Adapter | SendInput literal | SendInput keys | SendInput signal | ResizeSession | StreamSession |
|---|---|---|---|---|---|
| native (tmux) | `send-keys -l` | `send-keys` | maps to `C-c` etc. | no-op | `pipe-pane` → channel |
| docker | stdin via `attach` | stdin bytes | `docker kill -s` | resize API | `logs -f` non-TTY / `attach` TTY |
| k8s | `pods/exec` stdin | `pods/exec` stdin | eviction / signal via exec | `pods/exec` resize | **`pods/attach`** (NOT `logs -f`) |
| microVM | serial-console | serial-console | vsock signal | serial geometry | vsock stream |

### Constraint G-5 — IO lifecycle (nfr)

One persistent IO channel per session inside adapter, regardless of viewer count. Refcounted fan-out: HTTP handler subscribes/unsubscribes; adapter tears down underlying channel when refcount hits zero. Rationale: amortize k8s `pods/exec` TLS+auth handshake.

### Constraint G-6 — WSID multi-tenant boundary

`sessionID` stays opaque to callers. k8s adapter resolves `sessionID → (workspace, namespace, pod, container)` against in-flight WSID registry on every call. Native tmux ignores workspace dimension.

### Constraint G-7 — SPA file layout (schema)

  cards/{Assignment,Worktree,GitStatus,Beads,Escalations}Card.tsx

Modify `web/src/pages/SessionsPage.tsx` (Table/Workspace toggle) and `web/src/components/sessions/NewSessionDialog.tsx` (blank-session path). Add `@xterm/xterm` + `@xterm/addon-fit`.

### Constraint G-8 — Execution slices (rollout discipline)

Seven slices behind `?ws=1` flag until final cutover:
- A: output streaming (Streamable + SSE)
- B: input (POST /input + audit)
- C: status snapshot (GET /status)
- D: terminal pane (xterm.js)
- E: workspace shell (three-pane + toggle)
- F: right-pane cards
- G: blank-session dialog path

A-C ship independently and unblock CLI tools. D-G land sequentially behind flag, then flag-flip in one PR.

### Constraint G-9 — Risk envelope (nfr)

- `pipe-pane` lifecycle: tear down on session end or SSE disconnect; use `defer pipe-pane -O` on stream close — else tmux leaks named-pipe files.
- send-keys escaping: literal `-l` for printable; keyed path for control sequences; tests cover both.
- xterm.js bundle: ~120KB gzip, loaded lazily on first Workspace toggle.

### Constraint G-10 — Non-goals (v1)

No new top-level nav; no new auth model; no multi-cursor/collaborative editing; no webhooks beyond what beads provides.

## SPEC: Containerized sessions — architecture + threat model

- **source:** `docs/design/containerized-sessions.md`
- **precedence:** 1 (lower than gemba-lite)
- **type:** api-contract + nfr + schema + protocol
- **ratified:** 2026-04-24 (decision gm-nsdl/D9)
- **referenced epic:** gm-root.15

### Constraint C-1 — Backend abstraction refactor (api-contract)

Rename `Pane` → `Session` with `Kind` field (`tmux` | `container` | `ssh`). Keep `Pane` as type alias for one release. `SpawnSpec` grows optional fields: `Image`, `Mounts`, `Network`, `Secrets`, `Limits`. Validator at config-load time rejects mismatched combos (e.g. `Image` without `Kind=container`). Backend remains an interface; new backends are new files under `internal/adapter/native/backend/`.

### Constraint C-2 — Transport selection (protocol)

| Transport | When | Requires |
|---|---|---|
| Docker local daemon | gemba + docker on same host | docker CLI + daemon socket | 
| `DOCKER_HOST=ssh://user@vps` | gemba local, containers remote | ssh to remote, remote daemon |
| Pure SSH into container | gemba → container sshd | ssh client + sshd in image |

Rules: `DOCKER_HOST` honored when set; bind-mount paths must exist on remote (no rsync). `transport = "ssh"` selects SSH backend. SessionStore records which transport a live session uses. SSH is NOT a replacement for Docker backend (Docker is default for richer lifecycle).

### Constraint C-3 — SSH backend details (protocol)

- One keypair per agent **type**, not per session. Stored at `~/.gemba/keys/` 0600.
- `known_hosts` verified; fingerprint pinning supported. **Mandatory** strict host key checking — no `StrictHostKeyChecking=no` escape hatch.
- ProxyJump supported.
- Interactive: `ssh -tt`; one-shot: exec mode.

### Constraint C-4 — Security envelope defaults (nfr)

Docker backend applies unless overridden:
- `--read-only`, `--tmpfs /tmp:size=128M,mode=1777`
- `--cap-drop ALL`, `--security-opt no-new-privileges`
- `--user <uid>:<gid>` matching host workspace owner
- `--network none`
- `--pids-limit 512`
- `--memory` + `--cpus` from agent config (required)
- `--label gemba.session=<id>`, `--label gemba.agent=<agent-type-name>`

### Constraint C-5 — Threat model (nfr)

**In scope** (defend host from agent): host fs writes outside mounts; capability acquisition; data exfiltration via network; secret reads from env/proc; resource exhaustion; orphan survival across gemba crash.
**Out of scope**: kernel exploits, side-channels, malicious images themselves, multi-container coordinated compromise.

### Constraint C-6 — Unsafe-flag discipline (nfr)

`--privileged`, `--cap-add SYS_ADMIN`, `--network host` rejected by config validation unless `unsafe = true` on the container stanza. Loud in banner, logged on every spawn. Pattern precedent: `--dangerously-skip-permissions`.

### Constraint C-7 — Network policy modes (protocol)

| Mode | Semantics |
|---|---|
| `none` | `--network none`. Default. |
| `bridge:<name>` | `--network <name>`, lazy create. Operator-declared egress allowlist; gemba does NOT auto-write iptables in v1. |
| `host` | `--network host`. Requires `unsafe = true`. |

Named bridges shared across agent types referencing same name. Lifecycle: lazy create on first use; torn down on `gemba serve` exit. Pre-existing host bridges left alone.

### Constraint C-8 — Secret injection (nfr / protocol)

Never `--env` for secrets. Secrets declared by **name** in agents.toml. Resolver reads from `/etc/gemba/secrets/<name>` (0600) or operator-chosen host keyring (Keychain, libsecret). Backend mounts resolved secrets into container tmpfs at `/run/secrets/<name>` mode 0400. Mirrors Docker Swarm `--secret` shape.

Negative test required: after spawn with declared secret, value MUST NOT appear in `docker inspect`, `ps auxe`, or any gemba log.

### Constraint C-9 — Workspace volume model (api-contract / nfr)

Worktree on host: `~/.gemba/worktrees/<session-id>/` (same as tmux today). Bind-mount into container at agent-declared `cwd` (default `/work`). Container runs as host UID owning worktree — no post-hoc chown. If image entrypoint can't run as arbitrary UID, `uid_fixup = true` triggers chown on provision/teardown. EndSession atomic: removes container AND worktree. Failed teardown leaves `.gemba-zombie` marker; reaper reconciles on next start.

### Constraint C-10 — Lifecycle mapping (api-contract)

| OrchestrationPlaneAdaptor method | Docker verb |
|---|---|
| StartSession | `docker run -d` |
| SendKeys (interactive) | `docker exec -i` |
| SendKeys (one-shot) | `docker exec` no stdin |
| CapturePane | `docker logs --tail N` |
| PauseSession | `docker pause` |
| ResumeSession | `docker unpause` |
| EndSession | `docker stop` (SIGTERM, 10s grace) → `docker rm` |
| Kill | `docker rm -f` |

Container backend is the first real Pause/Resume implementation (tmux never had it).

### Constraint C-11 — Orphan reaper (nfr)

On `gemba serve` boot:
1. `docker ps -a --filter label=gemba.session --format '{{json .}}'`
2. Cross-check persisted session store.
3. Containers with gemba.session label and no live session → `docker rm -f`, log id+image+age.
4. Opt-out via `--no-reap`.

### Constraint C-12 — MCP compatibility (protocol)

1. Stdio MCP baked in image: no gemba involvement.
2. Network MCP on host: default `--network none` blocks; operator opts in via either (a) named bridge with host IP + MCP port in allowlist, or (b) bind-mount unix socket at `/var/run/mcp/<name>.sock`. **Unix-socket path preferred** (narrower, network policy stays locked).

### Constraint C-13 — Bridge-in-container (protocol)

`cmd/gemba-bridge` bind-mounted from host at `/opt/gemba/bridge` (read-only). bridge↔gemba traffic over unix socket bind-mounted at `/run/gemba/bridge.sock`. Bridge always reaches gemba regardless of `--network none`.

### Constraint C-14 — Preamble injection (protocol)

All three `PreambleStrategy` values work in containers:
- `claude_md` → written to bind-mounted CLAUDE.md in workspace; removed on EndSession.
- `first_message` → `docker exec -i <id> …` pipes preamble to agent stdin.
- `stdout_banner` → entrypoint wrapper echoes banner and execs agent.

### Constraint C-15 — agents.toml container schema (schema)

```toml
[[agent]]
name = "claude-code-sandboxed"
binary = "claude"
preamble = "claude_md"
hooks = "claude_code"
interaction_mode = "balanced"

[agent.container]
image = "ghcr.io/mikebengtson/gemba-claude:0.3.1"
cwd = "/work"
cpus = 2.0
memory = "4g"
pids_limit = 512
mounts = [
  { src = "{{workspace}}", dst = "/work", mode = "rw" },
  { src = "/opt/gemba/bridge", dst = "/opt/gemba/bridge", mode = "ro" },
]
secrets = ["anthropic_api_key"]
network = "none"
read_only_rootfs = true
# unsafe = true  # rejected unless explicitly set
```

Templates `{{workspace}}`, `{{session_id}}`, `{{agent_name}}` expand at spawn time. Validation rejects: `network="host"` without `unsafe=true`; `image` missing with `docker` backend; conflicting mount destinations; unknown secret names.

### Constraint C-16 — Pack-ins (schema)

`gemba init --pack {native|containerized|gastown}`. Selection persisted in `.gemba/pack.json`.
- `native`: tmux-backed; no container stanza.
- `containerized`: all agents carry `[agent.container]`; reference Dockerfiles in `deploy/containers/`; default images from `ghcr.io/mikebengtson/gemba-*`.
- `gastown`: OrchestrationPlane switches to Gas Town adaptor. Out of scope for this epic.

### Constraint C-17 — SPA backend badge (api-contract)

Session list rows display backend badge: `[tmux]`, `[docker]`, `[ssh]`. Container detail panel: image ref, resolved UID, network policy, cpus/memory caps, created-at, docker inspect (minus secret mounts). Spawn dialog picks backend when agent type allows multiple.

### Constraint C-18 — Kubernetes future-proofing (api-contract)

Backend interface must NOT assume container-id-is-a-string. Audit on landing:
- `Session.ID` opaque to callers (tmux: pane id; Docker: container id; Pod: `namespace/name`).
- `SpawnSpec` fields all map cleanly to k8s.
- Pod `Pending` state admitted: Spawn returns a Session; backend emits `session.started` or `session.failed_to_start` when scheduler places it. Synchronous backends fire event immediately.

Pod backend lands as `internal/adapter/native/backend/pod.go`. No further interface churn expected.

### Constraint C-19 — Observability (api-contract)

All container actions emit `GembaEvent`s on session stream with: `backend`, `container_id`, `image`, `network`, `exit_code` on End. Feeds existing `session.*` stream; no schema churn.

### Constraint C-20 — Release artifacts (schema)

- `ghcr.io/mikebengtson/gemba-bridge:<version>` — bridge binary, scratch image.
- `ghcr.io/mikebengtson/gemba-claude:<version>` — reference Claude image, forkable.
- `ghcr.io/mikebengtson/gemba-shell:<version>` — minimal shell sandbox.
- All multi-arch (amd64/arm64), Cosign-signed, syft SBOM attested.

### Constraint C-21 — Rollout sequence

1. Design sign-off
2. Backend interface refactor (no behavior change)
3. Docker backend + security defaults
4. agents.toml schema + validation
5. Workspace mount + lifecycle mapping
6. SPA surfacing
7. Pack-in `gemba-containerized` + reference images
8. Transports: `DOCKER_HOST=ssh`, then SSH backend
9. MCP + bridge-in-container hardening
