## ADR: GSD ↔ Beads bridge

- **source:** `docs/process/gsd-beads-bridge.md`
- **type:** ADR
- **status:** LOCKED (manifest-declared, precedence 0)
- **scope:** GSD process; Beads tracker integration; PLAN.md task schema; ROADMAP.md; gsd-executor lifecycle; label conventions; gemba-lite initiative bootstrap

### Decision statements (8, all LOCKED)

1. **D1 — Ownership split.** GSD owns the plan and the autonomous executor. Beads owns the durable, queryable tracker. No bidirectional sync daemon.
   - scope: tooling architecture

2. **D2 — Bridge is a naming convention.** GSD↔Beads integration is a thin naming convention applied at execute time. No background process, no schema mirroring.
   - scope: integration topology

3. **D3 — `bead:` field on every PLAN.md task.** Every task row in `PLAN.md` carries a `bead: <id>` reference (e.g. `bead: gm-v01.3.4`).
   - scope: PLAN.md schema

4. **D4 — Executor lifecycle around every task.** gsd-executor (or human stepping in) runs three calls per task:
   - claim: `bd update <id> --claim` before starting
   - note: `bd note <id> "<commit-sha> <subject>"` after each atomic commit
   - close: `bd close <id>` when acceptance passes
   - scope: gsd-executor contract

5. **D5 — Concept-to-bead mapping (immutable).**

   | GSD concept            | Beads concept            |
   |------------------------|--------------------------|
   | Project root           | Decision (root bead)     |
   | `ROADMAP.md` entry     | Milestone bead           |
   | Phase (gsd phase dir)  | Epic bead                |
   | Task in `PLAN.md`      | Story bead               |
   | Cross-AI review        | (no bead — gsd artifact) |
   | ADR / SPEC             | `note` on relevant bead  |

   - scope: bead hierarchy and prefix layout

6. **D6 — Reviews and verification logs are gsd artifacts, NOT bead rows.** gsd verification logs, cross-AI review markdown, plan-checker reports live as files under the phase dir; not as beads.
   - scope: artifact boundary

7. **D7 — Per-task atomic commits are bead `note` entries, NOT separate beads.** A single story bead accumulates one note per commit during execution.
   - scope: commit-to-tracker projection

8. **D8 — Cumulative label discipline (Beads does not auto-inherit).** Every bead must carry:
   - Initiative tag (e.g. `gemba-lite`)
   - All parent strategic tags (re-listed explicitly: `architecture`, `native`, `sessions`, `commercial`, …)
   - Layer tag (`core` | `server` | `spa` | `tmux` | `docker` | `k8s`)
   - Type tag (`decision` | `milestone` | `epic` | `story`)
   - scope: query correctness for `bd query 'labels CONTAINS …'`

### Bootstrap workflow (locked sequence)

1. `bd init --prefix <prefix> --non-interactive`
2. `bd create "Decision: <statement>" --labels <initiative>,decision,...`
3. Create Milestone bead with `--parent <decision>`.
4. Create Epics under the Milestone, one per planned phase.
5. Run `/gsd-ingest-docs` if `docs/design/` already carries the dispatch plan; else `/gsd-new-project`.
6. When `gsd-plan-phase` creates `PLAN.md`, add `bead: <id>` to each task row after creating the matching story bead under the Epic.
