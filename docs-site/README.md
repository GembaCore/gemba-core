# gemba docs site

Operator-facing documentation site for **gemba**, built with
[Astro Starlight](https://starlight.astro.build/).

The source-of-truth markdown lives in [`../docs/`](../docs). A small
sync step (`scripts/sync-docs.mjs`) mirrors that tree into
`src/content/docs/` at build time, prepending a `title:` frontmatter
field derived from the first H1 when one isn't already present. The
mirrored copy is gitignored — never edit it directly.

## Local development

```bash
cd docs-site
pnpm install
pnpm dev      # http://localhost:4321/gemba/
```

`pnpm dev` runs the sync step first, then `astro dev`. Changes to
`../docs/**/*.md` are picked up the next time the dev server restarts
(or you can re-run `pnpm sync` in another terminal).

## Build

```bash
pnpm build
```

Outputs a static site at `dist/`. The repo's `Makefile` exposes the
same targets:

```bash
make docs-dev    # pnpm dev
make docs        # pnpm build
```

## Deployment

The [`docs.yml`](../.github/workflows/docs.yml) GitHub Actions workflow
builds the site on every push to `main` and deploys it to GitHub Pages
at <https://mikebengtson.github.io/gemba/>.

## Design choice — why Astro Starlight?

The bead (gm-e14.4) allowed Docusaurus or Astro Starlight. Starlight
won because:

- The content is mostly static markdown — Astro's strength.
- Faster cold builds (Vite, no Webpack).
- Cleaner default theme than Docusaurus.
- Lower runtime JS surface (good for a docs site).

If we ever need React-heavy custom pages we can add the
`@astrojs/react` integration without leaving Starlight.

## Sidebar / navigation

The sidebar is configured explicitly in `astro.config.mjs` to give
operators a curated path through the doc set rather than a noisy
auto-generated tree. Sections:

1. **Getting started** — install, first run, parallelism.
2. **Concepts** — WorkPlane, OrchestrationPlane, Gemba walk (review of work in progress), code analysis.
3. **Adapters** — Beads, Gas Town, Native, plus their conformance docs.
4. **Personas** — PM, Documentarian, Deployment Engineer.
5. **API reference** — placeholder pointing at `docs/api/openapi.json`
   until gm-e4.2 lands an interactive explorer.
6. **Design docs** — the gm-* design tree, autogenerated.
7. **Deployment, Agents, Prior art & research** — collapsed by default.
